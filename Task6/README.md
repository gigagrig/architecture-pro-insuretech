# Ограничение запросов в Nginx

[nginx.conf](nginx.conf) ограничивает обращения к API до **10 запросов в минуту на IP-адрес клиента**. Превышение возвращает **HTTP 429 Too Many Requests**. Три сервера из исходного условия остаются в группе `backend_servers`.

## Настройки

| Директива | Назначение |
| --- | --- |
| `limit_req_zone $binary_remote_addr zone=per_client:10m rate=10r/m` | Хранит состояние лимита по IP в общей для рабочих процессов Nginx памяти размером 10 МБ |
| `limit_req zone=per_client` | Применяет ограничение ко всем запросам в `location /` |
| `limit_req_status 429` | Задаёт код ответа при превышении лимита |

Nginx распределяет допустимую частоту во времени: при `10r/m` проходит примерно один запрос в 6 секунд. Параметр `burst` не задан, поэтому серия из десяти быстрых запросов не разрешается: первый проходит, следующие сразу получают `429`. Отклонённые запросы не передаются бэкенду. Поведение описано в [документации модуля limit_req](https://nginx.org/en/docs/http/ngx_http_limit_req_module.html).

## Проверка

Файл является полной конфигурацией Nginx с блоками `events` и `http`. Его следует использовать как основной `nginx.conf`, а не помещать целиком в `conf.d`, который обычно подключается внутри `http`. Следующие команды выполняются в тестовом окружении без другого работающего экземпляра Nginx.

1. Замените `backend1.example.com`, `backend2.example.com` и `backend3.example.com` на адреса доступных тестовых бэкендов. Это адреса-заглушки из условия; они должны разрешаться в IP-адреса.
2. Проверьте конфигурацию командой `nginx -t -c /absolute/path/Task6/nginx.conf`. Запускайте её с правами, необходимыми для каталогов журналов и временных файлов вашей установки Nginx.
3. Запустите отдельный тестовый экземпляр с этим файлом: `nginx -c /absolute/path/Task6/nginx.conf`. Порт 80 должен быть свободен.
4. С одного компьютера выполните несколько запросов подряд: `curl -i http://127.0.0.1/`. Первый запрос должен получить ответ бэкенда, следующие — `429`.
5. Подождите 7 секунд и повторите запрос: он снова должен пройти к бэкенду. Запрос с другого IP имеет независимый лимит.
6. Остановите тестовый экземпляр: `nginx -s quit -c /absolute/path/Task6/nginx.conf`.

## Границы решения

В исходной конфигурации нет способа достоверно определить партнёра, поэтому ключом выбран IP-адрес. Несколько клиентов за одним внешним IP делят лимит; партнёр с несколькими адресами получает отдельный лимит на каждый. Для ограничения именно по партнёру нужен проверенный идентификатор из системы авторизации.

Если перед Nginx стоит балансировщик, необходимо настроить получение реального адреса клиента только от доверенных прокси. Иначе все запросы с адреса балансировщика попадут под один лимит. Непроверенный заголовок клиента использовать как ключ нельзя.

Общая память объединяет рабочие процессы одного экземпляра Nginx. Несколько независимых экземпляров имеют отдельные счётчики; для общего лимита между ними нужна дополнительная координация. Здесь применяется значение из задания — 10 запросов в минуту; исходная договорённость 20 запросов в секунду относится к общему описанию проекта.
